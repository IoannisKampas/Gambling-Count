# Roulette group patterns — implementation brief

A self-contained spec for implementing all ten readings in any language. Hand this file to an
agent as-is; it assumes no access to this repository.

Every number, count and event sequence below was generated by running the reference
implementation, not transcribed. `docs/PATTERNS.md` is the authoritative long-form document
(rationale, worked traces, per-reading discussion); this is the short form an implementer needs.

---

## 1. The task

Given a sequence of roulette spins (integers 0–36, oldest first), maintain **ten independent
counters**. Each counter watches for one shape in the sequence and goes one deeper each time that
shape resolves one way, or is wiped to zero when it resolves the other way.

```
count: 0 → −1 → −2 → −3 …     (never positive, never partial)
```

A counter is *how many deciders in a row have gone your way*. The useful signal is a count that
has got deep without being wiped.

### Hard constraints

1. **One reducer, ten rows of data.** The ten readings differ only by five numbers. Do **not**
   write ten functions, and do **not** write a "swap the groups" wrapper around a group-A
   implementation. Two copies of this logic disagreeing is the likeliest way to report a count
   that is not real.
2. **Keep it pure.** `applySpin(state, n, reading) -> {state, event}`. No I/O, no clock, no
   randomness, no logging. That is what lets you replay stored history through it and test it
   offline.
3. **Feed spins one at a time, oldest first.** Most sources hand you a window *newest first*.
   Reverse it before replaying, or every count is nonsense.
4. **Reject bad input loudly.** A value outside 0–36, or a non-integer, is not a spin. Do not
   coerce it and do not let it fall into a group.

---

## 2. The groups

Every number 0–36 belongs to group **A** or group **B**. The split is fixed and arbitrary — it is
not red/black, odd/even, or any standard bet.

| group | numbers | count |
|---|---|---|
| **A** | 0, 1, 2, 3, 6, 7, 8, 10, 13, 14, 17, 20, 23, 25, 26, 27, 28, 29 | 18 |
| **B** | 4, 5, 9, 11, 12, 15, 16, 18, 19, 21, 22, 24, 30, 31, 32, 33, 34, 35, 36 | 19 |

Two things implementers get wrong:

- **Zero is in group A.** Not neutral, not skipped, not a reset. An ordinary group-A spin that
  takes part in runs like any other.
- **The groups are different sizes** (18 vs 19), so they are not equally likely. This is a
  single-zero (European, 37-pocket) wheel. A double-zero wheel is not supported — you would have
  to decide where `00` goes before any of this means anything.

---

## 3. The shape

All ten readings watch for the same thing:

> a **run** of numbers from the same group, **interrupted** by the other group, and then **one
> spin that decides** what the interruption meant.

They differ in only three respects: **what it takes to arm**, **how long the interruption must get
before it is decided**, and **which way the decider has to go**.

State you need per reading:

| field | meaning |
|---|---|
| `count` | the counter, ≤ 0 |
| `phase` | `BUILDING` or `INTERRUPTED` (= armed) |
| `runGroup` | group of the current run |
| `runLength` | how long that run is |
| `originGroup` | while interrupted, the group whose run was broken |

Optionally also track `deepestCount` (minimum ever reached) and `resetCount`; neither can be
recovered afterwards.

---

## 4. The ten readings

This table **is** the specification. Everything else in this document follows from it.

| reading | minRunToArm | armsFrom | armAfter | decideAfter | deepensOnReturn |
|---|---|---|---|---|---|
| **All in 1** | 3 | either | 1 | 2 | **true** |
| **Monada** | 1 | **A** | 1 | 2 | false |
| **Diada** | 1 | **A** | 2 | 3 | false |
| **Triada** | 1 | **A** | 3 | 4 | false |
| **Ena/Duo** | 1 | **A** | 1 | **3** | false |
| **All in 2** | 3 | either | 1 | 2 | false |
| **Monada 2** | 1 | **B** | 1 | 2 | false |
| **Diada 2** | 1 | **B** | 2 | 3 | false |
| **Triada 2** | 1 | **B** | 3 | 4 | false |
| **Ena/Duo 2** | 1 | **B** | 1 | **3** | false |

- `minRunToArm` — how long a run must be before breaking it can arm anything.
- `armsFrom` — which group's run may arm. `either` (null) is what makes the All in pair
  symmetrical; `A` or `B` is what makes the other eight one-way.
- `armAfter` — how long the *interrupting* run must get to count as armed. Until then a return
  decides nothing: it is an interruption that gave up.
- `decideAfter` — how long the interrupting run must get for the interrupter carrying on to
  resolve the block.
- `deepensOnReturn` — `true`: the count deepens when the **original** group returns. `false`: it
  deepens when the **interrupting** group carries on.

### How to read the structure

Five readings, each with an opposite. The `2` suffix means *the opposite of*:

| | All in 1 | Monada | Diada | Triada | Ena/Duo |
|---|---|---|---|---|---|
| **opposite** | All in 2 | Monada 2 | Diada 2 | Triada 2 | Ena/Duo 2 |

- **All in 2 inverts the decider** (`deepensOnReturn`). Both All in readings arm on a run of three
  or more from *either* group.
- **Every other `2` exchanges the groups** — `armsFrom` and nothing else. Monada scores on `ABB`,
  Monada 2 on `BAA`, the shape Monada ignores.

The names give the arming depth: *monada* arms at **one** interrupting spin, *diada* at **two**,
*triada* at **three**. *Ena/Duo* names its two arms, at **one and two** — `armAfter` and
`decideAfter` set two apart instead of one, so it is armed from the first interrupting spin (a
return wipes it from there) but only the second arm can deepen it.

## 5. Reference implementation

```
applySpin(state, n, reading):
    g     = groupOf(n)              # throws if n is not an integer 0..36
    rules = RULES[reading]
    event = NONE

    if phase == INTERRUPTED:
        returned = (g == originGroup)

        if not returned and runLength + 1 < rules.decideAfter:
            # Armed, but the interruption is not yet long enough to be decided. It simply
            # lengthens and stays armed. Only the two Ena/Duo readings reach this.
            runLength = runLength + 1
            event     = ARMED

        else:
            deepens = returned if rules.deepensOnReturn else not returned

            if deepens:  count = count - 1 ; event = COUNT
            else:        count = 0         ; event = RESET

            phase       = BUILDING
            runGroup    = g
            runLength   = 1 if returned else 2     # never depends on the reading
            originGroup = null

    else:                                          # BUILDING
        if runGroup is null:
            runGroup = g ; runLength = 1

        else if g == runGroup:
            runLength = runLength + 1
            # An interruption already under way, now long enough to arm. Only a reading with
            # armAfter > 1 reaches this; for the rest the interrupting spin arms below.
            if originGroup is not null and runLength >= rules.armAfter:
                phase = INTERRUPTED ; event = ARMED

        else if runLength >= rules.minRunToArm
                and (rules.armsFrom is null or runGroup == rules.armsFrom):
            # A qualifying run has been broken. The interruption starts here; whether that is
            # already enough to arm depends on the reading.
            originGroup = runGroup
            runGroup    = g ; runLength = 1
            if runLength >= rules.armAfter:
                phase = INTERRUPTED ; event = ARMED

        else:
            # Deadzone — and an interruption that gave up before it armed is deadzone too.
            originGroup = null
            runGroup    = g ; runLength = 1

    return state, event
```

Three details that are easy to miss and change the results:

- **`originGroup` is set the moment a qualifying run is broken**, not when something arms. For
  `armAfter == 1` those are the same instant; for the deeper readings it is what remembers, across
  a half-built interruption, which group the decider is measured against.
- **The run bookkeeping after a decider never depends on the reading.** The group that returned
  stands alone, so it starts a run of 1; the group that carried on has been seen twice, so it
  carries a run of 2 into what follows. Getting this wrong makes chained shapes silently wrong
  while single shapes still pass.
- **An interruption that gives up before arming is deadzone**, not a reset. `ABA` under Diada
  fires *no event at all* and leaves a standing count exactly where it was.

### Events

| event | meaning |
|---|---|
| `ARMED` | a qualifying run was just broken (or the interruption lengthened while armed) |
| `COUNT` | the decider went your way; the count is one deeper |
| `RESET` | the decider went the other way; the count is back to 0 |
| `NONE` | an ordinary spin — building, extending, or chopping in the deadzone |

## 6. Acceptance tests

### 6.1 Numeric vectors (All in 1)

Each is a complete sequence fed to a fresh state; the expected value is the final count.

| sequence | final count | what it pins down |
|---|---|---|
| `3 6 7 18 0` | −1 | base case; the count fires on the return spin |
| `3 6 7 18 0 3 6 18 0` | −2 | the return spin seeds the next run |
| `0 0 0 4 0 4 4 4 0 4` | −2 | blocks run in either direction, and fire **no** resets |
| `3 6 7 18 0 1 2 3 18 4` | 0 | two consecutive opposites after a qualifying run wipe it |
| `3 6 7 18 0 4 1 4 1 3 6 7 18 0` | −2 | chop after a return is deadzone, not a reset |
| `1 2 4 5 5 4` | 0 | a run of 2 never arms, so no reset can fire |
| `3 6 7 8 10 18 0` | −1 | runs longer than 3 still qualify, and only once |
| `3 6 18 0 3 6 18 0` | −1 | the pivot seeds a fresh run that completes to 3 |

Vector 4 must fire exactly one `COUNT` then exactly one `RESET`. Vector 3 must fire **no** `RESET`
at all — a useful check, because an implementation that resets on any interruption still passes
several of the others.

### 6.5 Properties over random streams

Feed a few thousand pseudo-random spins (seeded, so failures reproduce) through all ten readings
and assert:

1. No count is ever positive.
2. Each reading's `deepestCount` equals the minimum count it ever observed.
3. **Swap invariance.** For each group-B reading, its count equals its group-A twin's count on the
   same sequence with every number moved to the other group. This is the entire specification of
   the mirrors in one assertion, and it catches a hardcoded group anywhere in the reducer.
4. **Ena/Duo ≤ Diada**, and **Ena/Duo 2 ≤ Diada 2** — they score on exactly the same spins, so the
   two-armed reading can only be wiped more often, never get deeper.
5. **Ena/Duo is armed exactly when Monada or Diada is armed**; likewise Ena/Duo 2 with Monada 2 or
   Diada 2. Its two arms cover their depths between them.
6. **At most one of Monada, Diada, Triada is armed at a time**; likewise at most one of Monada 2,
   Diada 2, Triada 2. Each wants a different interrupting-run length.
7. **No group-B reading ever scores on the same spin as its group-A twin.** Their deciders are
   mutually exclusive shapes.
8. Replaying the same sequence twice from a fresh state gives identical results.

## 7. Mistakes that look correct

These are real errors caught by the above tests, not hypotheticals. Each passes a majority of the
single-shape cases.

- **Treating a give-up as a reset.** `ABA` under Diada, `BAAB` under Triada 2. These must fire no
  event and leave a standing count alone. Recording them as resets quietly destroys counts that
  should have survived, and the shallower reading's shapes all still pass.
- **Assuming the shallower reading is always the deeper count.** This holds for Ena/Duo against
  Diada (property 4) because they score on the same spins. It does **not** hold between Monada and
  Diada, or between any two of the single-arm readings: Monada scores a spin earlier but is also
  wiped a spin earlier, so each gets ahead of the other regularly. If your tests only ever produce
  one ordering, something is wrong.
- **Over-generalising the arming exclusivity.** At most one of Monada / Diada / Triada is armed at
  once — but Ena/Duo is armed whenever Monada *or* Diada is, so "no two readings are ever armed
  together" is false. Do not assert it.
- **Giving a deeper reading the shallower one's `armAfter`.** Every `BAAAA`-style shape still gives
  the right count; only the near-miss shapes (`BAAB`, `BAB`) and the event sequences catch it.
- **Dropping `armsFrom`.** `ABB` scoring −1 under Monada 2, or `BAA` scoring 0 under it, both mean
  the group filter is not being applied.
- **Forgetting the carry.** `ABBABB` must be −2 under Monada. If it is −1, the scoring spin is not
  carrying a run of 2.
- **Reversing the window.** If every count looks plausible but disagrees with a hand-worked trace,
  check you are feeding oldest-first.

### Relative frequency, as a sanity check

A group-B reading is rarer than its group-A twin, because its *interrupting* group is group A, the
18-number one. A reading arming at depth *n* arms `(18/19)^(n−1)` as often as its twin and scores
`(18/19)^n` as often:

| | arms vs twin | scores vs twin |
|---|---|---|
| Monada 2 | **equal** | ≈5% less |
| Diada 2 | ≈5% less | ≈10% less |
| Triada 2 | ≈10% less | ≈15% less |
| Ena/Duo 2 | ≈2% less | ≈10% less |

Monada 2 arms exactly as often as Monada (one A and one B in either order are equally likely).
Ena/Duo 2 is the exception to the formula: with two arms its arming rate sums over both depths,
which nearly cancels the group-size difference. A group-B reading that appears to fire as often as
its twin at depth 2 or 3 means a dropped `armsFrom`.

Triada 2 is the rarest: ≈2.8% of spins, roughly one count every half hour on a table doing a spin
a minute. Expect long quiet stretches rather than assuming it is broken.

## 8. Feeding it real spins

The reducer is twenty lines and, once it passes §6, it is done. Getting the right spins into it, in
the right order, exactly once, is where implementations actually fail.

### 8.1 One spin, exactly once

Sources normally expose a rolling window of the last *N* results, newest first, with no notion of
what you have already seen. Between two reads you must work out which entries are new:

1. **If the source gives each round a stable id, use the ids.** Find the newest known id in the
   fetched list; everything above it is new. This is the only reliable method.
2. **Otherwise match by value overlap.** Find the offset at which the fetched window lines up with
   what you know, and take the entries above it. Guard it: a short window, or one containing
   repeated numbers, can align at more than one offset.

### 8.2 When you cannot tell, do not guess

If the new window shares nothing with what you knew, or aligns ambiguously, you have no way to
know how many spins you missed. **Discard the counts and flag the table desynced.** Do not assume
the window is all new, and do not assume nothing changed.

This is the most important rule here. A missed spin does not produce a slightly wrong count — it
produces a *plausible* count that is silently wrong from then on, and nothing downstream can
detect it. Losing a count costs you a count. Reporting a false one costs you trust in every count.

Record counts destroyed by a desync separately from counts wiped by a reading's own reset rule. A
desync is a failure to read the source, not the pattern resetting, and filing one as the other puts
a reset that never happened into your figures.

### 8.3 Starting up

If the source shows a window of recent results, replay it oldest-first to start from a true count
rather than zero. Two conditions:

- **Nothing you replay may notify anybody.** Those spins already happened. If you alert on deep
  counts, a replay that lands past your threshold must start already latched, so the alert fires
  on the next *live* spin that deepens it rather than on history.
- **Do not count replayed spins as observed.** Seeded spins restore the count but must not inflate
  statistics — they were watched by somebody else, or by nobody.

### 8.4 Cadence

Poll no faster than the table produces spins; a live wheel is one spin per 30–90 seconds, and
polling every few seconds only multiplies your chance of reading a half-updated page. Conversely,
watch for a window unchanged for far longer than a spin cycle — that is a dead feed, and it looks
exactly like a quiet table unless you check.

### 8.5 Tracking several readings at once

Advance every count **from the same loop, over the same spins, in the same order**. If one reading
is computed from a separately fetched history, the two will eventually disagree about the same
table for reasons that have nothing to do with the patterns.

Their statistics cannot be shared either: the spin that deepens one is the spin that resets
another, so "resets at depth 3" for one reading says nothing about the others. Spins observed, and
the period covered, are the only figures they have in common.

**Let only one reading raise alerts, and decide which.** Ten readings alerting on the same table at
different moments is noise rather than information.

## 9. Things that look like edge cases and are not

| case | what happens | why |
|---|---|---|
| `0` is spun | ordinary group-A spin | zero is not neutral here |
| run of 2 broken | nothing; new run of 1 | only runs of 3+ arm the All in pair |
| long chop `ABABAB` | nothing at all | the deadzone; a standing count is untouched |
| run of 6 then interrupted | arms exactly once | length beyond the minimum buys nothing |
| two interruptions in a row | impossible | the spin after arming always resolves it |
| count deepens twice on one spin | impossible | one decider per arming, one step per decider |
| a reset from −7 | count goes to 0 | resets are absolute, never partial |
| a long B-run under Monada or Diada | nothing, ever | they arm from group-A runs only |
| a long A-run under Monada 2 or Diada 2 | nothing, ever | they arm from group-B runs only |
| a single A under the All in pair | nothing | they need a run of three |
| `ABA` under Diada | nothing at all | the interruption stopped short; not a count, not a reset |
| `ABA` under Ena/Duo | a reset | armed from the first B, so the return wipes it |
| Monada and Diada armed together | impossible | one wants `AB`, the other `ABB` |
| Ena/Duo armed with Monada or Diada | **ordinary** | it is armed across both their depths |
| Ena/Duo deeper than Diada | impossible | they score together; Ena/Duo only loses more often |
| Monada deeper than Diada, or the reverse | ordinary | neither dominates the other |
| `ABBBB` under Monada, Diada and Triada | −1 for all three | a long enough interruption satisfies them all |
